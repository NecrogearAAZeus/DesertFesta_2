# 11.11 빼빼로데이 행사 — 스펙

> 원칙: **필요 없는 건 만들지 않는다.** 재사용 X, 하드코딩 OK.

## 1. 행사 개요
- 대상: FF14 부대원 + 링크 받은 약간의 외부 인원 (가입 제한 없음)
- 규모: 동시 접속 약 40명
- 진행: **게임 3개 × 20분**, 운영자가 버튼으로 진행
- 보상: 참여자 전원 빼빼로 기프티콘, 행사 후 이메일 수동 발송
- 환경: PC 웹 전용 (모바일 대응 안 함)

## 2. 확정 결정
| 항목 | 결정 |
|---|---|
| 점수 | **누적 없음.** 각 판의 등수만 가볍게 표시 |
| 참여 인정 | 게임에서 **직접 제출 1회 이상** (베팅 / 답 / 확장·흡수 선택). 채팅·로그인만·자동 부전승은 불인정 |
| 외부인 | 막지 않음 (가입 코드 없음) |
| 재접속 | 쿠키 세션으로 자동 로그인. 진행 중 판이 끝나면 다음 판부터 참여 |
| 비밀번호 분실 | 기능 없음. 운영자가 DB에서 직접 초기화 |
| 채팅 | 전체 공개, 지연 5초 이내, **3초에 1개 · 300자**. 전송 후 3초간 버튼 회색 |
| 동기화 | 1초 간격 폴링 |

## 3. 기술 스택
| 영역 | 선택 | 이유 |
|---|---|---|
| 서버 | Node.js + Express | 지난 행사 경험, 라우팅·정적 파일 |
| DB | SQLite (Node 24 내장 `node:sqlite`) | 파일 1개, 40명 충분. 설치·네이티브 빌드 없음. experimental 경고 1줄은 감수 (문제 시 better-sqlite3로 교체, API 거의 동일) |
| 비밀번호 | Node 내장 `crypto.scrypt` | 추가 라이브러리 불필요 |
| 세션 | 랜덤 토큰 쿠키 (`crypto.randomBytes`) + DB 저장 | 서버 재시작해도 로그인 유지 |
| 프론트 | 순수 HTML/CSS/JS | 빌드 없음 |
| AI | Anthropic API (`fetch` 직접 호출) | SDK 없이도 충분 |
| 배포 | Docker Compose + Cloudflare Tunnel | 집 PC, 포트포워딩 없이 HTTPS |

## 4. 파일 구조
```
server.js          공통: 가입/로그인, 세션, 채팅, 폴링, 운영자 API

games/ai.js        AI 생존게임

data/app.db        SQLite (Docker 볼륨)
Dockerfile

```

## 5. DB
```sql
CREATE TABLE users (
  id              INTEGER PRIMARY KEY,
  email           TEXT NOT NULL UNIQUE,
  ffxiv_id        TEXT NOT NULL UNIQUE,
  password_hash   TEXT NOT NULL,
  pepero          INTEGER NOT NULL CHECK (pepero BETWEEN 1 AND 5),  -- 맛 조사 후 이름 매핑
  consent_at      TEXT NOT NULL,     -- 개인정보 수집 동의 시각
  participated_at TEXT,              -- 첫 제출 시각. NULL이면 미참여
  created_at      TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE sessions (
  token      TEXT PRIMARY KEY,
  user_id    INTEGER NOT NULL REFERENCES users(id),
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```
- 채팅과 게임 상태는 **메모리**에만 둔다. (재시작 시 사라짐. 누적 점수가 없으므로 허용)
- 이메일·FF14 ID 중복 불가 → 기프티콘 중복 수령 방지

## 6. API
| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/signup` | 이메일, 비번, FF14 ID, 선호 빼빼로, 동의 → 가입 + 로그인 |
| POST | `/api/login` | FF14 ID + 비번 |
| GET | `/api/state?chatAfter=N` | 1초마다 호출. `{ me, game, view, chat[] }` |
| POST | `/api/chat` | 300자 이하, 3초 제한 (서버에서도 검사) |
| POST | `/api/act` | 현재 게임에 제출. 첫 제출 시 `participated_at` 기록 |
| POST | `/api/admin/:action` | 운영자 전용 (`x-admin-password` 헤더). `game`(전환) / `start`(판 시작. 결과 화면에서 다시 누르면 다음 판) / `resolve`(마감·결과 공개) |
| GET | `/api/admin/state` | 운영자 전용. 현재 게임·상태 |
| GET | `/api/admin/export` | 운영자 전용. 참여자 CSV (`participated_at` 있는 사람만). 기프티콘 발송용 |

## 7. 게임 약속 (모듈 인터페이스)
`server.js`는 아래 4개 함수만 호출한다. 게임 개발자는 자기 파일만 고친다.
```js
module.exports = {
  start() {},              // 판 시작 (운영자 start)
  act(user, input) {},     // 참가자 제출. user = { id, ffxivId }. 잘못된 입력이면 throw
  resolve() {},            // 운영자 마감 → 판정, 이번 판 등수 생성
  view(user) {},           // 이 사람 화면에 보낼 상태 (남의 비밀 선택은 숨김)
};
```
- 화면은 `public/games/<이름>.js`에 `GAMES.<이름>.render(el, state, act)`. 매초 호출되므로 처음 한 번만 뼈대를 만들고 이후엔 값만 갱신한다.
- 새 게임 등록: `server.js`의 `games` 객체, `index.html`의 `<script>`, `admin.html`의 `<option>` 각 1줄.

## 8. 게임 3개 (상세는 각 게임 문서)
| 순서 | 게임 | 한 줄 룰 | 개발 순서 |
|---|---|---|---|
| 1 | 빼빼로 경마 | 어느 빼빼로가 1등할지 사탕을 걸어라 | 1번째 |
| 2 | 확장/흡수 | 무작위 짝과 확장 또는 흡수를 고른다 (퀵채팅만, 홀수는 자동 +5) | 3번째 |
| 3 | AI 생존게임 | FF14 위기 상황에 대처법을 쓰면 AI가 생존/사망과 점수를 판정 | 2번째 |

- 행사 순서와 개발 순서는 다를 수 있음
- **중단선**: 일요일까지 3번째 게임이 안정되지 않으면 빼고 나머지 2개를 30분씩

## 9. 보안·개인정보
- 비밀번호 scrypt 해시, HTTPS (Cloudflare Tunnel)
- 가입 시 "기프티콘 발송 목적 수집, 행사 후 파기" 동의 체크 필수
- API 키·운영자 비번은 `.env`, 코드·git에 넣지 않음
- 행사 후: 참여자 이메일 CSV 추출 → 발송 → `data/app.db` 삭제

## 10. 만들지 않는 것
- 비밀번호 찾기, 이메일 인증, 자동 메일 발송
- 누적 점수·종합 순위
- 모바일 화면
- 웹소켓 (폴링으로 대체)
- 관리자 CRUD 화면 (문제·설정은 파일 수정 + 재시작)

## 11. 미정
- 선호 빼빼로 1~5의 실제 맛 이름 (조사 후)
- 각 게임 세부 룰 수치
- Cloudflare Tunnel 방식: 계정 없는 임시 주소(`trycloudflare.com`, 재시작하면 주소 바뀜) vs 도메인 연결
